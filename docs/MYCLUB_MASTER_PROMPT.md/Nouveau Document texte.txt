# 1. PRÉSENTATION DU PROJET

**Nom :** MyClub

**Organisation :** Club DIA — Digitalisation & Intelligence Artificielle.

**Objectif :**

Développer une plateforme web centralisée permettant de digitaliser et d'automatiser l'ensemble des activités administratives, organisationnelles et pédagogiques du Club DIA.

L'application doit permettre de gérer efficacement :

- Les utilisateurs et les huit rôles.
- Les demandes d'adhésion et les membres.
- Les projets et les équipes.
- Les tâches et leur avancement.
- Les événements et les inscriptions.
- Les présences et les participations.
- Les annonces et les notifications.
- Les statistiques et les tableaux de bord.
- Les paramètres et la configuration générale.

L'application doit présenter un niveau de qualité comparable à celui d'un véritable logiciel SaaS professionnel.

# 2. STACK TECHNOLOGIQUE OBLIGATOIRE

Respecter strictement les technologies suivantes :

### Frontend
- ReactJS.
- Vite.
- Tailwind CSS.
- React Router.
- Axios.
- Gestion centralisée des états lorsque nécessaire.
- Bibliothèque d'icônes professionnelle (Lucide React).
- Bibliothèque de graphiques adaptée (Recharts ou équivalent).

### Backend
- Python.
- Django.
- Django REST Framework.
- Django REST Framework SimpleJWT pour l'authentification JWT.
- Architecture API REST.
- Permissions personnalisées.
- Validation stricte des données.
- Documentation API avec Swagger / OpenAPI.

### Base de données
- PostgreSQL comme base de données principale et cible obligatoire.
- Django ORM.
- Migrations Django versionnées.
- Contraintes d'intégrité.
- Indexation et optimisation des requêtes.

### Architecture générale

Frontend React → API REST Django → PostgreSQL.

Le frontend et le backend doivent être clairement séparés et communiquer exclusivement à travers des API documentées.

Ne pas introduire MongoDB, Firebase ou SQLite comme base de données de production.

PostgreSQL est la base de données cible obligatoire.

Examiner la situation réelle des données existantes et les éventuelles sauvegardes MongoDB ou SQLite.

Réaliser une stratégie de migration fiable :

1. Identifier les sources de données.
2. Effectuer des sauvegardes.
3. Analyser les structures existantes.
4. Définir les correspondances entre anciennes et nouvelles structures.
5. Préparer les migrations Django.
6. Migrer les données lorsque cela est nécessaire.
7. Vérifier les relations et les contraintes.
8. Contrôler les nombres d'enregistrements.
9. Tester les fonctionnalités après migration.

Ne jamais prétendre qu'une migration est terminée sans vérification réelle.

Créer un fichier .env.example et utiliser des variables d'environnement pour les paramètres de connexion.
